# D. 反视觉垃圾

审查对象：网页、应用 UI、SVG、图表、插画、动效、生成的视觉内容。

设计规范由 `impeccable`、`frontend-design`、`canvas-design` 负责。本文件只判断两件事：**元素是否有目的**，**内容是否编造**。

## 判定原则

每个显眼的元素必须承担一项职责：建立层级、表达状态、指示操作、承载身份。说不出来就是在装饰。装饰不是罪，但装饰不能冒充信息。

## 检查清单

**模板化痕迹**
- 是否有常见的 AI 网页结构：大标题 + 副标题 + 三卡片 + FAQ + CTA，但内容空洞？
- 卡片是否只是因为「常见」而存在，而不是因为内容确实需要分组？
- 是否有装饰性的徽章、统计数字、客户 logo 墙，但没有真实来源？

**装饰**
- 渐变、玻璃拟态、光晕、阴影是否有明确作用（区分层级、表达状态）？
- 背景纹理、装饰图形是否和内容无关？
- 动效是否只是「让它动起来」，没有表达状态变化？

**布局**
- 是否存在为了填满空白而拉大的间距？
- 对齐、间距、字号是否来自同一套尺度，还是每个元素各自取值？
- 触摸目标是否至少 44×44 px？按钮、链接、图标控件都算。
- 各断点下是否出现横向溢出、文字出容器、卡片碰撞或移出屏幕、导航不可用？

**层级**
- 是否只有一个主视觉焦点？还是所有元素都在争夺注意力？
- 强调是否和重要性一致，还是和「看起来酷」一致？

**内容真实性**（与 C 维度重叠，这里重点看视觉化之后）
- 图表的数据是否有来源？
- 界面里的用户名、头像、数字是否来自提供的数据？
- 有没有虚构的产品功能、价格、评价、徽章？

**文字与排版**
- 渲染出来的文字是否有拼写错误、截断、换行错误？
- CJK 文本是否出现异常断行、标点挤压？
- 字号在实际显示尺寸下是否可读？
- 对比度是否达到 WCAG AA：正文 ≥ 4.5:1，大号文字（≥ 18px 或 14px 粗体）≥ 3:1？
- 文字若压在渐变、图片或纹理上，是否在整个覆盖区域都测过对比度，而不只是一个点？浅灰字压浅灰底、白字压局部偏亮的渐变都判不通过。

**性能机制**
- 每个 `<img>` / `<video>` / `<iframe>` 是否声明了 `width`/`height` 或 `aspect-ratio`？晚到内容（广告、嵌入、横幅）是否预留了空间？
- 首屏主图是否用 `<img>` 直接写在 HTML 里，且没有 `loading="lazy"`、带 `fetchpriority="high"`？
- `<head>` 里是否有阻塞渲染的第三方脚本？非关键脚本是否 `defer` / `async` 或按交互加载？
- 是否报告了未实测的 Lighthouse 分数或 Web Vitals 数字？没测就写「未测量」，不写估值。

**动画与生成视觉**
- 运动是否有明确的起点、终点、缓动和循环策略？
- 跨帧是否有角色比例、镜头、光照、静止元素的不一致？
- 运动主体是否全程在画面内？四肢、头、轮子、字幕、阴影是否被裁切？
- 是否在实际播放速度和尺寸下检查过？静态预览无法验证时间维度的质量。

**图表**
- 坐标轴、单位、图例是否完整？
- 是否有装饰元素被误读成数据（网格线、背景色块、渐变）？
- 数据点数量与呈现方式是否匹配（几十个点用散点，几千个点用聚合）？

## 不算视觉垃圾的情况

- 用户明确要求的视觉风格，即使朴素或繁复。
- 品牌规范强制的颜色、字体、装饰。
- 功能性动画（加载、过渡、反馈）即使简单。
- 复杂界面中的信息密度——只要每个元素都可解释。

## 验证要求

视觉交付的验证只能在渲染后进行。读代码、看 prompt、看 SVG 源码都不算。没有渲染环境时，状态记为 **Blocked** 或 **Not Run**，不要写成 Passed。

## 报告格式

```
[视觉] <页面/组件/文件:位置>
元素：<哪个视觉元素>
问题：<无目的 / 模板化 / 内容编造 / 层级冲突 / 穿帮>
证据：<在什么尺寸/状态下观察到>
建议：<删除 / 合并 / 调整层级 / 换成真实数据>
```
