# 评分标准

九个维度，每项 0/1/2 三档。0 = 明显缺陷，1 = 达到合格线，2 = 明显优于合格线。
每个非满分或零分维度必须摘录输出原文作为证据；没有证据的分数无效。

| 维度 | 0 分锚点 | 2 分锚点 |
|---|---|---|
| 正确性 | 产出物无法运行/结论错误/存在事实硬伤 | 全部可执行且经得起对照 |
| 任务完成度 | 漏掉任务明确要求的交付项 | 全部交付且边界处理完整 |
| 事实准确性 | 编造命令、API、数据或验证结果 | 每条操作性声明可溯源（file:line 或真实输出） |
| 可维护性 | 复制粘贴堆砌、命名混乱、无测试 | 结构清晰、改动最小、关键路径有测试 |
| 复杂度控制 | 无收益的抽象/依赖/配置 | 复杂度都有真实约束支付，无过度工程 |
| 视觉质量 | 元素无职责、模板化堆砌、穿帮 | 层级清晰、装饰有目的、多视口不破版 |
| 文档质量 | 套话、元话语、收尾客套、预算超标 | 定义句开头、祈使句、链接分流、预算内 |
| 多余内容 | 模板残留、无关重构、未经要求的章节 | 每个部分都能回答「删掉会损失什么」 |
| 执行成本 | 反复追问可推断的事、大量过程播报 | 提问只在真需要拍板时发生，汇报只报关键项 |

## 维度加权

不加权：总分仅用于排序，结论以逐维度差值表述。报告必须给出「哪个维度、
差几分、证据是什么」，不得只写总分。

## 与 Skill 规则的对应

文档质量维度对齐 SKILL.md 第 3/4 节；事实准确性对齐第 5 节；复杂度控制与
多余内容对齐第 4 节与 `references/anti-overengineering.md`；执行成本对齐
第 6 节成本纪律。评标时先按证据打分，再对照规则条目核对，顺序不能反——
先有证据，后有结论。
